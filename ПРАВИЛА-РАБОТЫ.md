# Правила работы в папке Web_Playdisplay

Над проектом одновременно работают несколько чатов: миниигра, контент и лендинг, AI-ассистент. Папка и репозиторий у всех **общие**, изоляции нет. Эти правила — не формальность: каждое написано после реальной поломки.

## 1. Ветку не переключать

Работа всегда идёт в `hybrid-v8`. Не выполнять `git checkout`, `git switch`, `git reset --hard` в общей папке.

*Почему:* рабочую копию оставили на `gh-pages` — папка `site/` стала выглядеть пустой, а файлы сайта оказались в корне. Правки в них уехали бы только в ветку раздачи и стёрлись при следующей пересборке.

## 2. `gh-pages` не пересобирать у себя

Пересборку ветки раздачи делает **только тот чат, который занимается деплоем**, и только в отдельном worktree, а не в рабочей папке.

*Почему:* команду выполнили в самой рабочей копии — `git archive … | tar -x` распаковал `site/` прямо в корень, а `git add -A` закоммитил плоскую копию всего сайта. В ветке оказались две копии: 337 файлов в корне и 328 в `site/`.

## 3. Никогда `git add -A` и `git add .`

Добавлять файлы **по именам**: `git add site/hero-scene.html`.

*Почему:* так в чужой коммит попадает работа соседнего чата — уже случалось. И так же в репозиторий уехала папка `samizdat` от другого проекта.

## 4. Перед работой — посмотреть, что в папке

```
git status && git log --oneline -1
```

Если видны незакоммиченные правки в файлах не своей территории — **не трогать их и не коммитить**. Сказать владельцу.

## 5. Территории

| Область | Файлы |
|---|---|
| Миниигра и 3D-сцена | `site/hero-scene.html`, `site/world*.js`, `site/*-lab.html` |
| AI-ассистент | `site/api/**` |
| Лендинг, контент, данные | `site/index.html`, `site/data/*`, `site/assets/*`, `*.md` |

`site/index.html` общий: в нём живут и лендинг, и панель ассистента, и связка с игрой (`pdGame`, `pdPlay`, лоадер). Правишь чужой блок в этом файле — сначала скажи владельцу.

## 6. Файлы массово не удалять

Не запускать `rm -rf`, `git clean`, `git rm -r` по широким маскам.

*Почему:* один раз с диска исчезли все 339 отслеживаемых файлов. Спасло только то, что всё было закоммичено.

## 7. Коммитить часто, пушить не реже

Работа в безопасности только после `git push`. Незакоммиченные правки теряются при любой операции с ветками — а её может сделать соседний чат.

## 8. Деплой — один непрерывный ритуал

```
коммит в hybrid-v8 → пересборка gh-pages → git push origin hybrid-v8 gh-pages → git pull на сервере
```

Между пересборкой и пушем никто не коммитит, иначе в раздачу уедет неполная картина. Деплоит один чат.

## 9. Признак столкновения

Правка не находит фрагмент, который точно был, или файл выглядит иначе, чем ожидалось, — файл изменил другой чат. **Перечитать файл, а не перезаписывать.**

## 10. Замки git

Песочница иногда оставляет `.git/*.lock`. Если git пишет «Another git process» — снять `.git/index.lock`, `.git/HEAD.lock`, `.git/objects/maintenance.lock` и повторить. Не делать `reset` и не пересоздавать репозиторий.
