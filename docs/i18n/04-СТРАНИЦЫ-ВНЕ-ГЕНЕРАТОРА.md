# Две страницы, которые генератор не делает

`privacy.html` и `404.html` собираются не из данных, а свёрстаны руками. Третий язык
им нужно добавить так же — руками.

Делать это **после** перевода: обеим нужен готовый текст.

---

## 4.1. `site/privacy.html` — правила обработки данных

### Как устроено сейчас

Два текста лежат в разметке рядом, переключаются на клиенте:

```html
<div data-lang="ru" class="on"> … русский текст … </div>
<div data-lang="en">            … английский текст … </div>
```

Скрипт в конце файла (строка 350) показывает нужный блок, ставит `<html lang>`, красит
кнопку и переписывает адрес на `?lang=en`. Язык берётся из адреса, иначе из
`navigator.language`.

Комментарий там объясняет, почему именно так: страница должна открываться **без сети
и без сборки** — её отдают юристу одним файлом.

### Что сделать

1. Добавить третий блок `<div data-lang="pt">` с переводом. Структура заголовков
   и разделов — один в один как у русского и английского.
2. Добавить кнопку `PT` рядом с существующими (`[data-go]`, блок `.lang`, строка 122).
3. Переписать выбор языка по умолчанию — сейчас он двоичный:

```js
// БЫЛО: всё, что не русское, считается английским
show((q || (nav === 'ru' ? 'ru' : 'en')) === 'ru' ? 'ru' : 'en');

// СТАЛО: три языка, незнакомый браузер — английский
var known = { ru: 1, en: 1, pt: 1 };
show(known[q] ? q : (known[nav] ? nav : 'en'));
```

4. Адрес в `history.replaceState` — `?lang=pt` по тому же правилу, что `?lang=en`.

### Осторожно

- **Числа в тексте продублированы словами и берутся из конфига ассистента**
  (срок хранения, размер файла, количество файлов). В `CLAUDE.md` записано:
  «Числа из конфига напечатаны на этой странице словами — менять надо в двух местах».
  В переводе они должны совпасть с русской и английской версиями. Не пересчитывайте
  и не округляйте.
- Это **черновик**, который должен дочитать юрист. В начале файла список того, что
  он должен дописать. Перевод черновика остаётся черновиком — не превращайте
  формулировки в утверждения, которых нет в оригинале.
- Страница живёт вне генератора: `python3 build_seo.py` её не трогает.

## 4.2. `site/404.html` — страница «не найдено»

### Как устроено сейчас

Одна русская страница. Отдаётся по `ErrorDocument 404 /404.html` из `site/.htaccess`
на **любой** несуществующий адрес — и на `/pt/чего-нибудь/` тоже. Внизу одна строка
по-английски: `English: playdisplay.com/en/`.

Появилась 18.09.2026, потому что до этого на несуществующем адресе отдавался голый
лист Apache, а приходят на такие адреса постоянно — по ссылкам со старого сайта,
которые Google до сих пор держит в выдаче.

### Что сделать

Сделать страницу трёхъязычной тем же приёмом, что у `privacy.html`: три блока
`data-lang`, переключение на клиенте.

**Язык выбирается по адресу, с которого человек сюда попал.** `ErrorDocument`
не меняет адрес в строке браузера, поэтому он доступен скрипту:

```js
// /pt/что-угодно → pt, /en/что-угодно → en, остальное → русский,
// а если браузер не русский — его язык, если мы его знаем
var p = location.pathname;
var code = /^\/pt(\/|$)/.test(p) ? 'pt'
         : /^\/en(\/|$)/.test(p) ? 'en'
         : ({ ru: 'ru', en: 'en', pt: 'pt' }[(navigator.language || 'ru').slice(0, 2).toLowerCase()] || 'ru');
```

Это лучше, чем один язык на всех: человек, пришедший по битой ссылке на `/pt/`,
не должен упираться в русский текст.

### Ссылки внутри страницы тоже языковые

На странице список разделов: `/#work`, `/services/`, `/concepts/`, `/library/`,
`/atlas/` и четыре ссылки на конкретные страницы работ и услуг. В португальском
блоке они должны вести на `/pt/...`, в английском — на `/en/...`.

**Проверьте, что цель существует.** Ссылки на `/work/vdnh-space-center/` и
`/work/stalingrad/` есть во всех языках, а вот телефон и почта — общие, их не трогать.

### Строка «English: …» заменяется

Сейчас внизу висит `<p class="en">English: …</p>`. С тремя языками это превращается
в переключатель — те же кнопки `[data-go]`, что на `privacy.html`. Отдельную строку
убрать, чтобы не было двух способов сменить язык на одной странице.

### Проверка

`.htaccess` на превью не исполняется, поэтому проверять так:

```bash
python3 serve.py
# http://localhost:8000/404.html        — русский
# http://localhost:8000/404.html?lang=pt — если оставите поддержку ?lang
```

Выбор по `location.pathname` локально не проверить — там всегда `/404.html`.
Проверяется на боевом после деплоя: зайти на `playdisplay.com/pt/несуществующее/`.
**Это единственная часть задания, которую до деплоя проверить нельзя.** Напишите
об этом в отчёте, чтобы владелец проверил руками.
