# 3D-сцена и мини-игра: почему там русский и что с этим делать

Самая объёмная часть задания. Итог: **37 строк** сцены и игры становятся
переводимыми, плюс один набор символов на лендинге.

Переводить самому не надо. Надо сделать так, чтобы строка приехала в выгрузку.

---

## Диагноз

На `/en/` мини-игра и часть сцены говорят по-русски. Причин пять, и они разные.

### 1. Сцена переводит себя ОДИН РАЗ и больше никогда

`site/hero-scene.html`, строка 754:

```js
addEventListener('DOMContentLoaded', function(){
  if (!window.PD_I18N) return;
  var w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT, null), n;
  ...
});
```

Один проход по дереву при загрузке — и всё. **Наблюдателя за новыми узлами, в отличие
от лендинга, нет.** На лендинге (`site/index.html`, ~1154) стоит `MutationObserver`,
который переводит всё, что код дорисовал позже. В сцене его нет.

Игра рисует свой интерфейс **после** загрузки: HUD, события полёта, экран результата,
таблицу рекордов, онбординг. Ни одна из этих строк перевода не видит никогда.

### 2. Готовый механизм есть, но применён в трёх местах из сорока

`window.PD_T(x)` объявлен там же (строка 749) и работает: берёт `window.PD_I18N` и отдаёт
перевод по точному совпадению. В местах вывода он вызывается **трижды** — строки 3202,
6854, 6908 (плюс служебный вызов внутри самого прохода, 767). Остальные строки
выводятся напрямую.

Самый наглядный пример — подпись событий полёта. `gLabel(t)` (строка 6437):

```js
function gLabel(t) {
  gameLabel.textContent = t;                       // перевода нет
  …
  _lblT = setTimeout(() => { gameLabel.textContent = 'ЭНЕРГИЯ СОБРАНА'; … }, 1600);
}
```

Через неё проходят **все** события полёта, и она же через 1,6 секунды возвращает
подпись в исходное состояние — русским литералом. Причём `'ЭНЕРГИЯ СОБРАНА'` **есть**
в английском словаре: копия этой строки лежит в разметке (строка 820) и переводится
при загрузке. То есть на `/en/` подпись стартует по-английски, а после первого же
события навсегда становится русской.

### 3. Подписи проектов в сцене пишутся в обход перевода

```js
// hero-scene.html:6898
document.getElementById('ap-meta').textContent = d.sub;
// hero-scene.html:6966
arcSub.textContent = d.sub;
```

`d` — запись из `ARC_DATA` (~6675), где `title` и `sub` лежат русскими литералами:
`'Ростех-Экспо'`, `'Росатом · 2024'`. На английской версии так и показываются.

### 4. Набор символов «дешифровки» кириллический

`site/index.html`, ~1718:

```js
var GLYPHS = 'АБВГДЕЖЗИКЛМНОПРСТУФХЦЧШЩЭЮЯ0123456789/\\|<>#*+=·';
```

Строка `#hkLine` перебирает случайные символы, пока «проявляется» очередное слово.
Слова (`Музеи`, `Выставки`…) словарь переводит, а мусор при дешифровке остаётся
кириллическим: **на английской странице латинское слово проявляется из кириллицы.**

### 5. Строки с подстановкой словарём непереводимы в принципе

```js
'ОПАСНОСТЬ · ' + alt.toFixed(1) + ' М'
```

Словарь ищет точное совпадение целой строки, а здесь в середине число. Такую строку
надо разбирать на куски — иначе её нельзя перевести никаким словарём.

---

## Решение: оборачивать в момент вывода

**Каждая строка, которую увидит человек, оборачивается в `PD_T()` там, где она
попадает на экран.**

### Почему не наблюдатель, как на лендинге

Соблазн велик: один `MutationObserver` на сцену — и все сорок строк переведутся
сами. Так делать **нельзя**. Игровой цикл трогает DOM каждый кадр: HUD, счётчики,
всплывающие события. Наблюдатель окажется на горячем пути и будет обходить поддеревья
шестьдесят раз в секунду ради строк, которые меняются раз в несколько секунд.

`PD_T()` в точке вывода — это один поиск по объекту тогда и только тогда, когда
строка действительно меняется. Дешевле, предсказуемее, и видно в коде.

### Как строка попадает в перевод

Обёртка **и есть** пометка «это увидит человек». `_tools/i18n_export.py` сам находит
`PD_T('…')` и `T('…')` в `hero-scene.html` и `index.html` и добавляет найденное
в батчи (функция `wrapped_strings`).

**Отдельного списка вести не надо. Обернули — строка приедет в выгрузку сама.**

Проверить, что строка видна сборщику:

```bash
python3 -c "import sys; sys.path.insert(0,'_tools'); from i18n_export import wrapped_strings; print(*wrapped_strings(('index.html','hero-scene.html')), sep='\n')"
```

## Правила обёртывания

### Правило 1. Литерал — прямо внутри вызова

Сборщик ищет литерал непосредственно в скобках `PD_T(`. Выражение внутри он не разберёт.

```js
// НЕТ — в выгрузку не попадёт (так сейчас написана строка 3202)
PD_T(play.state === 1 ? 'ПРОЕКЦИЯ АКТИВНА' : 'ПРОЕКЦИЯ ВЫКЛЮЧЕНА')

// ДА
play.state === 1 ? PD_T('ПРОЕКЦИЯ АКТИВНА') : PD_T('ПРОЕКЦИЯ ВЫКЛЮЧЕНА')
```

**Строку 3202 поправить по этому правилу.** В работе она не сломана: `PD_T` получает
уже вычисленную строку и переводит её. Сломано другое — сборщик этих литералов не
видит, и **в португальский словарь они не попадут**. Английский их имеет только потому,
что кто-то однажды внёс их руками. Третий язык на это рассчитывать не может.

### Правило 2. Числа и разделители остаются в коде

```js
// БЫЛО
gameDanger.textContent = 'ОПАСНОСТЬ · ' + alt.toFixed(1) + ' М';

// СТАЛО
gameDanger.textContent = PD_T('ОПАСНОСТЬ') + ' · ' + alt.toFixed(1) + ' ' + PD_T('М');
```

Переводится **слово**, а не строка с числом. Разделитель `·`, пробелы и само число —
код, их не переводят.

То же для `'РЕДКАЯ ЭНЕРГИЯ · +' + n`, `'СЕРИЯ ×' + n`, `'ВЫ — ' + pos + ' МЕСТО ИЗ ' + count`.

У последней «ВЫ — N МЕСТО ИЗ M» порядок слов в португальском другой. Соберите её
из двух переводимых кусков так, чтобы перевод мог их переставить:

```js
meEl.textContent = PD_T('ВЫ —') + ' ' + d.pos + ' ' + PD_T('МЕСТО ИЗ') + ' ' + d.count;
```

Если при переводе выйдет коряво — вынесите всю фразу шаблоном с `%s`, но тогда
подстановку делайте `String.replace`, а не конкатенацией, и **сохраните оба `%s`**:
импорт проверяет, что подстановки не потерялись.

### Правило 3. Шаблонные литералы разбирать

```js
// БЫЛО
`DPR ${qDpr.toFixed(2)} · плотн. ${(qScale * 100 | 0)}%`
```

Такие строки есть только в отладочном слое — их **не переводим** (см.
[05-НЕ-ПЕРЕВОДИТЬ.md](05-НЕ-ПЕРЕВОДИТЬ.md)). Если появится такая в пользовательском
тексте — разбирайте по правилу 2.

### Правило 4. Canvas — тоже вывод

HUD полёта частично рисуется на канве:

```js
// hero-scene.html:6265
g.fillText('КМ/Ч', C_X - R - 40 * SS - HOUT, C_Y + 3 * SS - HUP);
```

DOM тут нет, но правило то же: `g.fillText(PD_T('КМ/Ч'), …)`. Перевод длиннее
оригинала — **проверьте, что подпись не наезжает на кольцо**: `KM/H` короче, но
в других строках может быть иначе.

### Правило 5. Регистр не трогать

HUD набран прописными. Оборачивайте строку **как она есть**, прописными:
`PD_T('ПОЯС АСТЕРОИДОВ')`. Переводчик вернёт прописные латиницей. Не заменяйте это
на `text-transform: uppercase` — в португальском прописные сохраняют диакритику,
и браузерное преобразование её местами теряет.

### Правило 6. Ключ словаря — это сама русская строка

После правки по правилу 2 ключ меняется: было `'ОПАСНОСТЬ · '`, стало `'ОПАСНОСТЬ'`.
Это нормально и ожидаемо — выгрузка возьмёт новый ключ. Но если такая же строка уже
есть в `site/data/i18n/en.js`, английский перевод к новому ключу не привяжется: старый
ключ останется сиротой, новый будет без перевода. **Английский словарь после правок
надо будет добрать** — это отдельная задача владельца, в вашу не входит. Просто не
удивляйтесь, увидев это в отчёте проверки.

### 2.1. Мини-игра: HUD, события, онбординг — 14 строк

`site/hero-scene.html`. Обернуть в `PD_T()` по правилам выше.

| Строка | Текст | Где |
|---|---|---|
| 1434 | `ВЕДИ ПАЛЬЦЕМ ПО ЭКРАНУ` | онбординг, набирается посимвольно `obType()` |
| 1527 | `<b>Ведите пальцем по экрану</b> — корабль повторяет движение` | подсказка первого экрана |
| 1529 | `КРЕСТИК СЛЕВА ВВЕРХУ — ВЕРНУТЬСЯ В ПОРТФОЛИО` | подсказка |
| 4163 | `ЗОЛОТАЯ НИТЬ ЦЕЛИКОМ · +200` | событие полёта |
| 5789 | `ПОЯС АСТЕРОИДОВ` / `КАНЬОНЫ ВПЕРЕДИ` | смена участка трассы, тернарник → правило 1 |
| 5835 | `СКВОЗЬ КОЛЬЦО · +5 · УСКОРЕНИЕ` | событие |
| 5868 | `РЕДКАЯ ЭНЕРГИЯ · +` | событие с числом → правило 2 |
| 5869 | `СЕРИЯ ×` + число, иначе `ЭНЕРГИЯ СОБРАНА` | тернарник с числом → правила 1 и 2 |
| 6442 | `ЭНЕРГИЯ СОБРАНА` | сброс подписи внутри `gLabel` — **легко пропустить** |
| 5899 | `БРЕЮЩИЙ ПОЛЁТ · +2` | событие |
| 6017 | `ОПАСНОСТЬ · ` + высота + ` М` | → правило 2 |
| 6265 | `КМ/Ч` | канва → правило 4 |

**Осторожно с `obType()` (1434).** Она набирает строку посимвольно с эффектом
печатной машинки. Перевод другой длины — проверьте, что строка не вылезает за экран
на телефоне в портрете.

**Оборачивать надо внутри `gLabel`, а не в местах вызова.** Через неё проходят все
события, и — главное — она сама возвращает подпись русским литералом через 1,6 секунды
(строка 6442). Обёртка в местах вызова этот сброс не закроет.

```js
function gLabel(t) {
  gameLabel.textContent = PD_T(t);
  …
  _lblT = setTimeout(() => { gameLabel.textContent = PD_T('ЭНЕРГИЯ СОБРАНА'); … }, 1600);
}
```

`PD_T` принимает переменную, перевод найдётся по значению. Но тогда литералы в местах
вызова сборщику не видны — **добавьте `gLabel` в регулярку `TCALL`**
в `_tools/i18n_export.py`:

```python
TCALL = re.compile(r"""(?<![A-Za-z0-9_$.])(?:PD_T|T|gLabel)\(\s*(['"])((?:[^'"\\]|\\.)*?)\1""")
```

Проверьте после правки, что в выгрузке появились «СКВОЗЬ КОЛЬЦО · +5 · УСКОРЕНИЕ»
и соседи.

### 2.3. Подписи проектов в сцене — 14 строк

`site/hero-scene.html`, `ARC_DATA` (~6675). Полный список —
[строки/сцена-подписи-проектов.csv](строки/сцена-подписи-проектов.csv).

Здесь **не надо** оборачивать сами литералы в `ARC_DATA`: это данные, а не вывод.
Обернуть надо две точки вывода:

```js
// 6898
document.getElementById('ap-meta').textContent = PD_T(d.sub);
// 6966
arcSub.textContent = PD_T(d.sub);
```

`PD_T` принимает переменную — перевод найдётся по значению. Но тогда строки
`ARC_DATA` в выгрузку **не попадут** (сборщик ищет литералы). Поэтому дополнительно:

- проверьте `title` — где он выводится, там тоже нужен `PD_T`;
- добавьте все 15 пар `title`/`sub` в выгрузку. Проще всего — научить
  `_tools/i18n_export.py` читать `ARC_DATA` из `hero-scene.html` так же, как он
  читает `CARDS` из `_tools/og.py` (функция `og_cards()`, разбор через `ast` —
  здесь понадобится разбор JS, достаточно регулярки по строке вида
  `title: '…', sub: '…'`). Отдельным разделом `scene` в `collect()`.

**Годы и знаки `·` не переводятся.** `'Росатом · 2024'` → `'Rosatom · 2024'`.
Имена собственные — как в английской версии: Rostec, Rosatom, VDNH, UEC.
Проверить можно по `site/data/en/projects.json` — там те же проекты уже названы
по-английски.

### 2.4. Набор символов «дешифровки» — 1 строка

`site/index.html`, ~1718. Обернуть:

```js
var GLYPHS = T('АБВГДЕЖЗИКЛМНОПРСТУФХЦЧШЩЭЮЯ0123456789/\\|<>#*+=·');
```

На лендинге функция перевода называется `T`, не `PD_T` (объявлена в строке 803).

В словаре к этой строке ляжет латинский набор. В инструкцию переводчику это попадёт
как обычная строка, поэтому **допишите подсказку** в `_tools/i18n_export.py`,
функция `item_note()` — по образцу подсказки для `prose/nbsp_words`:

> NÃO traduza. Escreva o conjunto de caracteres equivalente: as letras maiúsculas
> do alfabeto latino usadas em português, os algarismos e os mesmos símbolos.

**Проверьте на глаз.** Если перевод вернёт набор другой длины — ничего не сломается,
но эффект «дешифровки» может стать реже или гуще. Смотреть на `/pt/`, первый экран,
строка под заголовком.

## Чего в этой задаче НЕТ

- Шрифты. Проверено: подмножество `latin` в `site/assets/fonts/fonts.css` покрывает
  U+0000–00FF, вся португальская диакритика там. TTF для карточек превью
  (`_tools/fonts/`) тоже содержат `áàâãçéêíóôõú` — сверено по таблице cmap.
  **Ничего с шрифтами делать не надо.**
- Перевод. Строки переводит владелец через ChatGPT.
- Панель настроек сцены, отладочный слой, загрузчик моделей, проверки раскладки
  клавиатуры — см. [05-НЕ-ПЕРЕВОДИТЬ.md](05-НЕ-ПЕРЕВОДИТЬ.md).

## Как проверить свою работу

```bash
# 1. строки видны сборщику
python3 -c "import sys; sys.path.insert(0,'_tools'); from i18n_export import wrapped_strings; print(len(wrapped_strings(('index.html','hero-scene.html'))))"
# сейчас 6. После задач 2.1, 2.2 и 2.4 — около 30, после [03](03-АССИСТЕНТ.md) — около 60.
# Точное число зависит от того, как разложите строки с числами по правилу 2.

# 2. выгрузка собирается и словарь вырос
python3 _tools/i18n_export.py pt

# 3. сайт по-прежнему собирается
python3 build_seo.py

# 4. игра не сломалась: открыть, взлететь, разбиться, открыть рекорды
python3 serve.py   # затем http://localhost:8000/
```

Пункт 4 обязателен. `PD_T` возвращает исходную строку, если словаря нет, —
по-русски всё должно выглядеть **ровно как раньше**.
