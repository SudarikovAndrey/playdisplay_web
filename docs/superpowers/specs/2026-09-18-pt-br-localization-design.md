# Локализация сайта на бразильский португальский (pt-BR)

Дата: 18.09.2026. Решения приняты владельцем.

## Что делаем

Третья языковая версия сайта, паритетная английской: главная-SPA, 15 кейсов,
9 услуг + хаб, концепции, Атлас, библиотека оборудования, плюс `privacy.html`.
34 страницы, как сейчас у `/en/`.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Вариант | pt-BR (Бразилия) | Решение владельца |
| Путь | `/pt/` | Заложен в комментариях кода и в `.htaccess` |
| `<html lang>` | `pt-BR` | Язык контента бразильский |
| `hreflang` | `pt` | Версия одна. `pt-BR` отдал бы португальцев в `x-default`, а это русская главная |
| `og:locale` | `pt_BR` | |
| Данные | `site/data/pt/*.json`, `site/data/i18n/pt.js` | Как у английского |
| Перевод | ChatGPT, батчами по ~9 000 знаков | Решение владельца |

## Архитектура

Двуязычие уже построено под третий язык — шапка `build_seo.py` описывает ровно
этот путь. Работа не в том, чтобы его изобрести, а в том, чтобы убрать из
генератора бинарные развилки `if L.code == 'en' else <русский>`: с третьим языком
каждая такая развилка молча отдаёт русский текст на португальской странице.

### Что становится данными

- `LANGS` получает поля `html` (атрибут `lang`) и `hreflang` — раньше оба брались
  из `code`, а у pt-BR они расходятся: `code` = `pt` (пути и словарь),
  `html` = `pt-BR`, `hreflang` = `pt`.
- Новая таблица `LANG_TEXT[code]` — проза, живущая рядом с генератором:
  подвал, лиды хабов услуг/концепций/Атласа, заголовок и мета главной,
  подписи библиотеки (`LIB_T`). Русские и английские значения переезжают
  в неё БЕЗ ИЗМЕНЕНИЯ: вывод для `/en/` обязан остаться байт в байт прежним.
- Сборка падает, если у языка из `LANGS` нет записи в `LANG_TEXT`. Молчаливый
  откат на русский — ровно то, что мы убираем.
- Переключатель языков в шапке статических страниц — цикл по `LANGS`, а не
  свёрстанные две кнопки.
- Блок `/en/index.html` → функция `build_home(L)`, вызываемая для каждого
  неруского языка.

### Проверки

Словарь работает по ТОЧНОМУ совпадению русской строки, и промах не ошибка —
это тихий русский текст на чужой странице. Поэтому:

1. **Отчёт покрытия**: сколько строк главной не нашли перевода, со списком.
2. **Скан кириллицы** по готовым `/pt/**` с белым списком имён собственных.
   Пока скан не чист — `/pt/` не открываем.

Существующее утверждение о совпадении slug-ов между языками начнёт держать
португальский автоматически.

## Конвейер перевода

- `_tools/i18n_export.py` — раскладывает `_i18n/pt/in/<раздел>-NN.json`:
  только переводимые строки, каждая со своим путём до поля, плюс шапка-промпт.
- `_tools/i18n_import.py` — собирает ответы из `_i18n/pt/out/` в
  `site/data/pt/*.json` и `pt.js`, сверяя ключи, slug-и и полноту полей.

Владелец носит батч в ChatGPT и кладёт ответ рядом. Сборка и проверка — на агенте.

## Ассистент и речь

- `pd_langs()['pt']['speech']`: `pt-PT` → `pt-BR` (комментарий в коде предусматривает
  ровно эту замену).
- `GUESS` и кнопки `SLANGS` в `index.html` — туда же.
- В промпте перевода карточки «на португальском» → «на бразильском португальском»:
  без уточнения модель отдаёт европейский вариант.

## Запуск

`site/.htaccess` сейчас держит `RewriteRule ^pt(/.*)?$ → /en/ [R=301]`.
Снимается ПОСЛЕДНИМ шагом, когда `/pt/` собран и скан кириллицы чист.
До этого раздел невидим, и незаконченный перевод в выдачу не попадёт.

## Порядок работ

1. Рефакторинг генератора + `pt` в `LANGS`. Промежуточное состояние —
   `/pt/` собирается с русскими текстами, это нормально и невидимо снаружи.
2. Экспорт батчей → перевод → импорт.
3. OG-карточки: `CARDS_PT` в `_tools/og.py`, дальше скрипт рисует сам.
4. `privacy.html` — вручную.
5. Ассистент и речь.
6. Скан кириллицы → снятие редиректа → деплой.

## Чего НЕ делаем

- Не переводим закрытые презентации (`/ball/`, `/avtovaz/`, `/jurere/`, `/cifra/`,
  `/kit/`, `/mare/`, `/boxingcartel/`, `/poemiq/`): это отдельные документы вне
  генератора. `/jurere/` португальскую версию получит своим проходом, не этим.
- Не переносим раздел ОКПД2 на страницу услуг pt — классификатор российский,
  на английской его тоже нет намеренно.
- Не трогаем `site/landing.css` напрямую: он собирается из `_src/landing.css`.
