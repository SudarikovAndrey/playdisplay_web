# AI-ассистент: как это устроено и как включить

Ассистент даёт посетителю сайта выговориться, по ходу вытаскивает смыслы и присылает
Андрею готовый бриф письмом. Интерфейс живёт в `site/index.html` (панель `#ai`),
вся серверная часть — здесь.

## Устройство

```
api/ai.php              ← единственная точка входа. POST JSON, поле action
api/lib/util.php        ← конфиг, ответы, сессии-файлы, лимиты, HTTP-клиент
api/lib/prompts.php     ← ХАРАКТЕР РАЗГОВОРА. Правится без кода, начинать надо отсюда
api/lib/llm.php         ← драйверы моделей: mock / anthropic / openai_compat / gigachat
api/lib/brief.php       ← вёрстка письма (HTML + текстовая версия)
api/lib/mailer.php      ← доставка: file / smtp / mail
api/selftest.php        ← страница проверки настроек, на боевом закрыта
api/config.sample.php   ← образец конфига. Ключей в репозитории нет и быть не должно
api/sessions/           ← стенограммы и счётчики (создаётся сама, наружу закрыта)
api/outbox/             ← письма драйвера file (создаётся сама, наружу закрыта)
```

Действия: `ping` (есть ли бэкенд), `start`, `turn`, `brief`, `send`.
Клиент знает только про `api/ai.php`. Ключей в браузер не попадает ничего.

## Что нужно сделать, чтобы включить

1. `cp site/api/config.sample.php site/api/config.php` — файл в `.gitignore`.
2. Вписать драйвер модели и ключ, драйвер почты и адрес.
3. Открыть `/api/selftest.php` — страница прогоняет весь путь и показывает, что не сходится.
4. На боевом сервере конфиг лучше положить **выше веб-корня**: `~/wordpress_2/pd-ai-config.php`.
   `ai.php` ищет его там сам, `config.php` рядом с кодом тогда не нужен.
   Раскомментировать обратно закрытие `selftest.php` в `api/.htaccess`.

Локально — одной командой из корня проекта:

```
./ai-local.sh
```

Скрипт проверяет php, поднимает его на 8000 и сразу говорит, дошёл ли запрос до бэкенда
и подключена ли модель. Нужен php (`brew install php`).

**Важно: `serve.py` для ассистента не годится.** Он отдаёт файлы и умеет перемотку видео,
но php не выполняет — панель ассистента на нём уходит в демо-режим и показывает
заранее заготовленный бриф, что бы человек ни говорил. Порт у обоих 8000, и это легко
спутать. Для сайта без ассистента `serve.py` по-прежнему удобнее (видео листается),
для ассистента нужен `./ai-local.sh`.

## Без настройки тоже работает

Без конфига драйверы `mock` + `file`: разговор идёт по прошитому сценарию, бриф собирается,
письмо кладётся в `api/outbox/*.html`. Это нужно, чтобы проверить интерфейс и вёрстку письма
до подключения платного API. Ассистент в этом режиме честно говорит человеку, что письмо не уйдёт.

На превью GitHub Pages PHP не выполняется — клиент это распознаёт (ответ не JSON)
и уходит в демо-режим сам, без ошибок в консоли.

## GigaChat: что нужно знать до подключения

Выбран драйвером по умолчанию. Три вещи, на которых легко потерять вечер.

**1. Сертификат обязателен.** Хост GigaChat подписан НУЦ Минцифры, которого нет в стандартном
хранилище ни на macOS, ни на большинстве серверов. Без него не проходит даже получение токена
(`CERTIFICATE_VERIFY_FAILED`). `./ai-local.sh` качает сертификат сам в `site/api/certs/`;
вручную — `curl -k https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt -o
site/api/certs/russian_trusted_root_ca_pem.crt`. Драйвер подхватывает файл по этому пути
автоматически. Проверку сертификата мы не отключаем — подставляем правильный корень.

**2. Бесплатный режим не подходит.** Freemium (250 млн токенов Lite) даётся
«исключительно для личного некоммерческого использования». Ассистент на сайте студии —
коммерческое, нужен платный пакет. Минимальный: 20 млн токенов Lite за 1 300 ₽ на 12 месяцев.

**3. Цены** за 1 млн токенов, одинаковые для физлиц и юрлиц (проверено 31.07.2026):
Lite `GigaChat-2` — 65 ₽, Pro `GigaChat-2-Pro` — 500 ₽, Max `GigaChat-2-Max` — 650 ₽.
Одна цена за токен, без деления на входные и выходные.

**Языки.** GigaChat в документации Сбера — «русскоязычная модель», её бенчмарки только
`ru` и `en`. Португальский не заявлен. Поэтому язык → драйвер задаётся в конфиге:

```php
'llm' => 'gigachat',                              // русский и английский
'llm_by_lang' => array('pt' => 'openai_compat'),  // португальский другим сервисом
```

Языки перечислены в одном месте — `pd_langs()` в `lib/prompts.php`: код страницы, локаль
распознавания речи (`ru-RU`, `en-US`, `pt-BR`) и первый вопрос. Клиент берёт язык из
`<html lang>`, локаль речи подтверждает сервер. Разговор идёт на языке посетителя,
**бриф Андрею всегда приходит по-русски**, а цитаты остаются на языке человека.

## Сколько это стоит

Одна сессия — 5 минут речи, 9 обменов репликами: **26 500 токенов** (24 700 входных,
1 800 выходных). Считано по самим промптам, не на глаз. Расход почти не зависит от того,
сколько человек говорит: платится в основном системный промпт, который уезжает заново
на каждую реплику.

**Распознавание речи — 0 ₽ при любой длительности.** Оно идёт в браузере через Web Speech API.

| GigaChat-2-Pro, 500 ₽/млн | 13,3 ₽ | пакет 3 млн за 1 500 ₽ → 113 брифов |
| GigaChat-2-Max, 650 ₽/млн | 17,2 ₽ | |

У GigaChat одна цена за токен, у OpenAI вход и выход считаются по-разному. Рубли — по курсу 95.

## Где стоит бэкенд, тот и определяет доступность модели

Частая путаница: кажется, что можно отдавать OpenAI иностранным посетителям, а GigaChat —
российским. **Так не работает.** Запрос к модели идёт не из браузера гостя, а с нашего сервера.
Стоит `ai.php` на timeweb — все запросы уходят с российского адреса, и OpenAI откажет
независимо от того, кто открыл сайт.

Разделение возможно, но по другой линии: **по месту, где стоит бэкенд**.

```
playdisplay.com  → timeweb + GigaChat            (llm => 'gigachat')
/en/, /pt/       → копия ai.php на другом хосте  (llm => 'openai_compat')
```

Что для этого есть в коде:

- `API_BY_LANG` в `site/index.html` — адрес бэкенда для отдельных языков.
- `cors_origins` в конфиге зарубежной копии — какие домены ей разрешено обслуживать.
- `llm_by_lang` — если оба языка идут на один бэкенд, но разными драйверами.

Юридическую сторону (условия OpenAI смотрят на то, кто пользуется сервисом, а не только
откуда пришёл пакет) стоит обсудить с юристом, а не решать на уровне конфига.

## Качество диалога важнее цены

Разница между моделями видна не в счёте, а в том, как звучит вопрос: живое «Кто эти школьники —
местные или приезжают?» против «Уточните целевую аудиторию проекта». Проверять на
`/api/selftest.php`: страница показывает, какой вопрос модель задала на тестовую реплику
и какой бриф собрала из тестовой стенограммы. Драйвер меняется одной строкой, промпты
от модели не зависят — можно попробовать две-три и оставить ту, чьи вопросы звучат лучше.

## Что происходит, когда модель недоступна

Разговор не упирается в стену: вопросы берутся из запаса в `pd_fallback_question()`,
бриф уходит со стенограммой и пометкой «модель не разобрала». Письмо доходит всегда —
если почтовый сервер отказал, копия остаётся в `api/outbox/`. Ошибки пишутся
в `api/sessions/error.log`.

## Страж от ботов

Перед началом разговора браузер обязан решить подписанную сервером задачу: найти такое
число, чтобы `sha256(nonce:число)` начинался с 16 нулевых бит. Это около 65 тысяч хешей —
0,1 секунды на компьютере, 0,3 на слабом телефоне. Человек этого не замечает: работа идёт
в те секунды, пока он читает первый экран панели, и к нажатию микрофона пропуск уже готов.
Если не готов — вокруг кнопки появляется кольцо из точек, которое заполняется настоящим
прогрессом перебора, а не декоративной анимацией.

**Почему проверка на сервере, а не только в браузере.** Бот не открывает страницу, он бьёт
прямо в `api/ai.php`. Любая проверка, которая живёт только на клиенте, обходится удалением
одной строчки JS. Здесь же `start` без верного решения и подписи не проходит вовсе.

Что именно не даёт себя обойти:

- задача подписана HMAC — подделать или занизить сложность нельзя, состояние на сервере не хранится;
- задача привязана к адресу — решённую на одной машине не раздать сотне ботов;
- одноразовость — тот же nonce второй раз не принимается;
- срок жизни 10 минут;
- сложность растёт с каждой сессией с одного адреса (до 19 бит), потом включается лимит.

**Вторая ступень.** Если поведение похоже на скрипт (браузер сам сознался в автоматизации
через `navigator.webdriver`, ни одного события ввода, панель открыта за 40 мс, окно
нулевого размера), сервер просит подтверждение: точка бежит по кругу, надо нажать в
подсвеченном секторе. Работает мышью, касанием и с клавиатуры — иначе проверка отсекала бы
людей, которые не пользуются мышью. По эвристикам **никогда не отказываем**, только
показываем эту ступень: человек за клавиатурой и человек со скринридером выглядят
«подозрительно» ровно так же, как бот.

**Честно о границах.** Proof-of-work — это лежачий полицейский, а не стена. Серверный бот
на нативном коде считает 65 тысяч хешей за 13 миллисекунд. Он останавливает дешёвый
массовый перебор и делает бессмысленным примитивный скрипт, но целеустремлённого
злоумышленника не остановит. Реально держат нагрузку три вещи вместе: лимит сессий
на адрес, обязательный подписанный обмен (нельзя просто дёрнуть `start`) и одноразовость
решения. Если однажды понадобится настоящая стена — на это место без переделок встанет
Cloudflare Turnstile: интерфейс уже умеет показывать вторую ступень.

Настройки — `guard_bits`, `guard_bits_max`, `guard_off` в конфиге. Проверка работоспособности —
строка «страж от ботов» на `/api/selftest.php`.

## Защита

- Ключи только в конфиге, конфиг не в git; на боевом — выше веб-корня.
- `api/.htaccess` закрывает конфиг, `lib/`, `sessions/`, `outbox/` и `selftest.php`.
- Лимиты в конфиге: сессий с адреса в час, реплик в сессии, знаков в реплике.
- Адрес посетителя в стенограмме не хранится — только его хеш.
- `keep_transcripts => false` выключает хранение стенограмм после отправки письма.
