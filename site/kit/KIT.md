# Конструктор презентационных страниц PLAYDISPLAY

Набор блоков, из которых собрана книга «Музей Мяча», плюс приёмы лендинга. Нужен для
одного: собрать новую презентационную страницу за час, а не за неделю, и не переоткрывать
задачи, которые уже решены. Всё, что однажды ломалось, записано в поле `traps` описи —
это не украшение, это самая ценная часть.

## С чего начать чату, который собирает новую страницу

1. Прочитать `blocks.json` — опись блоков. Там у каждого: зачем он, какая нужна разметка,
   какие файлы подключить, какие есть опции и на чём люди спотыкались.
2. Открыть живой каталог: `python3 serve.py` в корне проекта и
   `http://localhost:8000/kit/catalog.html`. В каталоге каждый блок **отрендерен**, а рядом
   показана **его же разметка** — она печатается из самой демонстрации, поэтому не может
   разойтись с видом.
3. Создать скелет страницы: `python3 site/kit/new-page.py имя-страницы "Заголовок"`.
   Скелет уже подключает кит в правильном порядке и содержит первый экран, главу и подвал.
4. Собирать страницу из блоков каталога. Своё писать только тогда, когда подходящего блока
   нет — и тогда сразу дописать его в кит (см. ниже).

## Что где лежит

```
site/kit/
  KIT.md          ← этот файл: принципы и порядок работы
  blocks.json     ← опись блоков: зачем, разметка, опции, подводные камни
  catalog.html    ← живой каталог: блоки видно и код рядом
  new-page.py     ← скелет новой страницы (умеет и закрытую по паролю)
  css/            ← layout · typography · components · animations · scrub
  js/             ← boot · reveal-cursor · nav · parallax · lists · hotspots
                    xray · courts · ball · ui · scrub · catalog
  parts/          ← фрагменты разметки для сборки страниц
  assets/demo/    ← лёгкие примеры для каталога (кадр, рентген-слой, ролик, портрет)
```

**Порядок подключения важен.** CSS: `layout → typography → components → animations`
(и `scrub.css`, если нужна крутилка). JS с `defer`:
`boot → reveal-cursor → nav → parallax → lists → hotspots → xray → courts → ball → ui`
(и `scrub`). Порядок не случайный: `layout` задаёт токены и сетку, на которые опираются
остальные файлы; `boot` должен успеть закрыть страницу до того, как остальное начнёт
рисовать.

## Как расширять кит

Это не библиотека «на почитать», а живой инструмент. Правило одно:

> **Придумали новый блок или приём — сразу положите его в кит.**
> CSS/JS в `kit/`, запись в `blocks.json`, демонстрацию в `catalog.html`.
> Иначе следующий чат изобретёт то же самое заново и сделает иначе.

Демонстрация добавляется так: в `catalog.html` внутри `<template id="kbDemos">` положить
`<div data-block="ваш-id"> …настоящая разметка… </div>`. Каталог сам напечатает её в блоке
«Разметка» и сам посчитает, не осталось ли блоков без демо — строка состояния наверху
показывает расхождение честно.

Если блок живёт только на своей странице (как WebGL-переход лендинга), запись в описи
всё равно нужна: с полем `inCatalog: false` и указанием, где смотреть живьём. Знать о
существовании приёма важнее, чем иметь его копию.

## Принципы, на которых собран этот кит

- **Комментарий объясняет ПОЧЕМУ, а не что.** «Здесь fillRect, потому что круги в кадр не
  укладывались» — полезно. «Рисуем прямоугольник» — нет.
- **Числа в оформлении проверяются замером.** Порог шва — долей площади, зазор — пикселями,
  габарит — измерением в браузере. На глаз ошибиться легко: порог футбольного шва, взятый
  «на глаз», отдавал шву 70 % шара.
- **Правку видно на картинке.** Прежде чем сказать «готово», посмотрите: скриншот, замер
  геометрии в браузере, прогон кода в node с выводом в PNG. Половина ошибок в этом ките
  найдена именно так, а не чтением кода.
- **Сначала причина, потом настройка.** Если что-то выглядит не так, ищите, почему так
  выходит. Разметка площадок «складывалась не в ту сторону» не из-за коэффициента, а из-за
  того, что камера стояла за той гранью.
- **Одна задача — один проход.** Это про модель в ассистенте, но верно и здесь: не
  смешивайте в одном изменении содержание и оформление.

## Правила общей папки

- Книгу `site/ball/private/page.html` **не править**: это выпущенный документ. Кит живёт
  отдельно и развивается свободно.
- Лендинг `site/index.html` — чужая территория, там работают другие чаты. Приёмы оттуда
  переносим в кит копией, сам лендинг не трогаем.
- Перед правкой — `git status`. В папке одновременно работают несколько чатов.
- Коммит — по именам файлов, никогда `git add -A`.
- Деплой запускает владелец: `./deploy.sh "что сделали"`. Из чата до хостинга не дотянуться.

## Что чинилось в ките и почему это важно помнить

- **Кегель на телефоне задаёт самое длинное слово, а не вкус.** Крупный шрифт не переносится
  внутри слова: блок не может стать уже своего длинного слова и вылезает за экран вместе со
  всей страницей. Замер на экране 401 px: `h1` при 23vw давал «ПАЦАНА» 502 px (вылет 141),
  крупная фраза при 13vw — «заканчивается» 485 px. Сейчас 15vw и 10.5vw, вылет ноль.
  Проверка простая: свернуть окно до 400 px и сравнить `scrollWidth` с `clientWidth`.
- **`1fr` в сетке — это `minmax(auto, 1fr)`**, то есть снизу он ограничен шириной содержимого.
  Длинная подпись в плитке раздвигала полосу за экран. Везде, где колонки должны делиться
  поровну, стоит `minmax(0, 1fr)`.
- **Правила внутри `.chapter-copy` сильнее одиночного класса блока.** `.chapter-copy p`
  обнуляло `margin: auto` у цены, и в двух карточках разной длины она расходилась по высоте
  на 24 px. Блокам, живущим внутри главы, нужна специфичность из двух классов.
- Все три ошибки нашлись ЗАМЕРОМ в браузере, а не чтением кода. Так и проверять.

## Живая 3D-сцена: что выяснилось на гараже с NIVA (16.08.2026)

`site/avtovaz/garage.html` — конфигуратор: модель крутится, красится, поднимается на
подвеске, колёса выворачиваются. Всё это на модели, которая пришла ОДНОЙ сеткой без
разделения на детали. Что стоило времени:

- **Модель из Meshy весит 63 МБ и содержит 1,95 млн треугольников.** В веб она едет только
  после `gltf-transform optimize --simplify-ratio 0.045 --texture-size 1024`: 3,7 МБ и
  88 тысяч треугольников, разница на глаз незаметна.
- **`--compress meshopt` не включать**, если грузите штатным GLTFLoader r128 без декодера.
- **Чересстрочная раскладка вершин ломает наивную выборку.** После оптимизации атрибуты
  лежат в общем буфере (interleaved), и чтение `attribute.array[i * itemSize]` даёт кашу из
  осколков. Читать только через `getX/getY/getZ`.
- **Колёса выделяются из общей сетки** цилиндрами у нижних углов габарита, центры считаются
  в два прохода (второй — уточнение по точкам внутри первого цилиндра). За один проход в
  «колесо» уезжала половина бампера.
- **Перекраска запечённой текстуры маской по насыщенности или светлоте НЕ РАБОТАЕТ.** Замер
  гистограммы прямо в браузере: 99 % текселей с насыщенностью ниже 0.1, 94 % — в полосе
  светлот 0.1–0.3. Кузов от резины по картинке не отличить; отделять надо геометрией, а
  краску вешать только на материал кузова.
- **Главная ловушка: `metalness = 1` у импортированной модели.** У полного металла нет
  диффузной составляющей, и кузов показывает только отражения ламп — краска не видна вовсе,
  сколько ни правь шейдер. Крашеный кузов — это `metalness ≈ 0.2`, `roughness ≈ 0.42`.
- **Колесо мыши внутри сцены перехватывать нельзя** (только с Shift): иначе рамка съедает
  прокрутку и документ застревает на сцене.
