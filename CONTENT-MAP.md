## Что было не так и куда это уехало

Причина путаницы: **три поколения сайта лежали в одной папке**, и все три отслеживались git.

| Что | Было | Стало |
|---|---|---|
| Старый сайт «Бренд-платформа 2026» | корень: `index.html`, `css/`, `js/`, `assets/`, `about|contact|projects.html` — 12 МБ, 24 файла в git | `_ARCHIVE/1 - старый сайт 2026/` |
| Сборка 3D-прототипа | `dist/` — 91 МБ, 13 файлов в git | `_ARCHIVE/2 - прототип 3D/` |
| Исходники 3D-сцены | `proto 3d/` — `.blend`, `.fbx`. Был прописан в `.gitignore`, но игнор не действует на уже отслеживаемые файлы | `_ARCHIVE/2 - прототип 3D/` |
| Слепки `site/` — 490 МБ, уникального ничего | `dist_upload/` (копия от 21 июля), `site.zip`, `dist.zip`, `ziVRGV2O` (дубль `pdf_images_VMF.zip`) | `_ARCHIVE/3 - копии текущего сайта/` |
| Сырьё и инструменты — 571 МБ | `videos/` (мастера), `concepts raw/`, `remade/`, `picture converter/`, `pdf-slides-extractor/` | `_ARCHIVE/4 - рабочие материалы/` |
| Документы чужого проекта | два `.docx` про АМГ-окна и тех.регламент | `_ARCHIVE/5 - документы другого проекта/` |

Наработки 3D-прототипа никуда не делись: они живут в `site/model.js`, `site/odk_frame.js`, `site/textures.js`, `site/hero-scene.html`.

`.gitignore` переписан: раньше в нём были строки, которые ничего не давали (`proto 3d/`, `dist.zip` дважды, `videos/raw_videos/` при уже игнорируемом `videos/`).

## Что осталось решить

### 1. Ветки — разобрано 29.07.2026

Было шесть, осталось две. `master`, `proto-3d`, `gh-pages-new`, `gh-pages-ready` закрыты
тегами `archive/*` и локально удалены; на GitHub остались как резерв. Ничего не потеряно:
у `proto-3d` уникальных коммитов не было вовсе, единственный уникальный коммит
`gh-pages-ready` держится тегом. Заодно убран дубль-remote `origin2`.

| Ветка | Что это |
|---|---|
| `hybrid-v8` | **вся работа идёт здесь** |
| `gh-pages` | только превью на GitHub Pages. В доставке больше не участвует |

`origin/HEAD → origin/main`, а `main` содержит один «Initial commit» — поэтому GitHub по
умолчанию открывает пустую ветку. Осталось поправить: в настройках репозитория сделать
`hybrid-v8` веткой по умолчанию.

### 2. Деплой — переделан 29.07.2026, цепочка из одного звена

```
site/ на Маке  ──rsync по SSH──►  ~/wordpress_2/public_html  ──►  playdisplay.com / .ru
```

Одна команда: `./deploy.sh "что сделали"`. Подробно — `README-ДЕПЛОЙ.md`.

**Почему ушли от git-доставки.** Было три звена: пересборка `gh-pages` руками → пуш на
GitHub → `git pull` по SSH на хостинге. Вставало каждое. Настоящая причина застреваний
нашлась не в ветках: папка, смонтированная в песочницу Claude, разрешает создавать файлы,
но не удалять. Git создаёт `.git/index.lock` и снять его не может — лок остаётся навсегда,
и следующий коммит из любого чата падает с «Another git process seems to be running».
Плюс пересборка `gh-pages` прямо в рабочей папке разложила сайт в двух копиях, а
`git add -A` затащил в ветку раздачи `_ARCHIVE` (1056 МБ) и `production` (473 МБ) —
и весь этот архив раздавался с боевого сайта. Ветка `gh-pages` пересобрана начисто.

GitHub остался резервом истории: скрипт пушит `hybrid-v8` в конце, и если пуш не прошёл,
на сайт это не влияет. `.github/workflows/deploy-pages.yml` отключён на ручной запуск.

`.htaccess` лежит в репозитории (`site/.htaccess`) и приезжает вместе с сайтом.

### 2а. Переезд в корень домена — сделано 28.07.2026

Было: в корне `playdisplay.com` стоял WordPress 2021 года, новый сайт прятался в `/new/` под запретом индексации, каноникалы указывали на корень, то есть на чужой сайт.

Стало:

```
~/wordpress_2/
  public_html/          ← новый сайт, В КОРНЕ домена. Обновляется rsync'ом с Мака
    old/                ← статичный слепок старого сайта, noindex. rsync его не трогает
    .git/               ← остаток прежнего git-клона, в доставке не участвует
  wp_old_root/          ← сам WordPress, вынесен из веба. База не тронута
```

Проверено снаружи после переезда: главная и страницы кейсов отдаются, `robots.txt` разрешает индексацию, `sitemap.xml` и `data/atlas.json` на месте, `/.git/` закрыт (403), `/projects/`, `/about/`, `/contact/`, `/wp-admin/`, `/xmlrpc.php` редиректят, `/old/` жив. `playdisplay.ru` отдаёт тот же сайт с canonical на `.com`.

Редиректы со старых адресов работ: 7 сменили адрес (`аэропорты-россии` → `airports`, `одк-оак` → `odk-oak`, `ростех-экспо` → `rostec`, `судостроение` → `industry-rf`, `vdnh_space` → `vdnh-space`, `vdnh_space-2` → `vdnh-space-center`, `stallingrad` → `stalingrad`), 8 совпадают, 6 отсутствующих уходят в `/old/work/<slug>/`. Проверено на живых адресах.

Осталось: убрать поддомен `products.playdisplay.com` (сейчас отдаёт новый сайт; по нему расходилась PDF-презентация, так что удаление убьёт внешние ссылки на неё) и продлить домен `playdisplay.com` — оплачен до 18 августа 2026, регистратор внешний.
