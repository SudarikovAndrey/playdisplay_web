## Что было не так и куда это уехало

Причина путаницы: **три поколения сайта лежали в одной папке**, и все три отслеживались git.

| Что | Было | Стало |
|---|---|---|
| Старый сайт «Бренд-платформа 2026» | корень: `index.html`, `css/`, `js/`, `assets/`, `about|contact|projects.html` — 12 МБ, 24 файла в git | `_ARCHIVE/1 - старый сайт 2026/` |
| Сборка 3D-прототипа | `dist/` — 91 МБ, 13 файлов в git | `_ARCHIVE/2 - прототип 3D/` |
| Исходники 3D-сцены | `proto 3d/` — `.blend`, `.fbx`. Был прописан в `.gitignore`, но игнор не действует на уже отслеживаемые файлы | `_ARCHIVE/2 - прототип 3D/` |
| Слепки `site/` — 490 МБ, уникального ничего | `dist_upload/` (копия от 21 июля), `site.zip`, `dist.zip`, `ziVRGV2O` (дубль `pdf_images_VMF.zip`) | `_ARCHIVE/3 - копии текущего сайта/` |
| Сырьё и инструменты — 571 МБ | `videos/` (мастера), `concepts raw/`, `remade/`, `picture converter/`, `pdf-slides-extractor/` | `_ARCHIVE/4 - рабочие материалы/` |
| Документы чужого проекта | два `.docx` про АМГ-окна и тех.регламент | `_ARCHIVE/5 - документы другого проекта/` |

Наработки 3D-прототипа никуда не делись: они живут в `site/model.js`, `site/odk_frame.js`, `site/textures.js`, `site/hero-scene.html`.

`.gitignore` переписан: раньше в нём были строки, которые ничего не давали (`proto 3d/`, `dist.zip` дважды, `videos/raw_videos/` при уже игнорируемом `videos/`).

## Что осталось решить

### 1. Ветки: шесть, нужных две

| Ветка | Последний коммит | Что это |
|---|---|---|
| `hybrid-v8` | 27.07 | **актуальная работа** |
| `gh-pages` | 27.07 | **то, что реально раздаётся** |
| `proto-3d` | 22.07 | отстала на 49 коммитов, целиком входит в `hybrid-v8` |
| `gh-pages-ready` | 22.07 | отстала на 25 коммитов |
| `gh-pages-new` | 22.07 | отстала на 25 коммитов |
| `master` | 04.07 | старый сайт 2026 |

Плюс `origin/HEAD → origin/main`, а `main` содержит один «Initial commit» — поэтому GitHub по умолчанию открывает пустую ветку. Это главная причина ощущения «непонятно, где сайт».

Предложение: закрыть `master`, `proto-3d`, `gh-pages-new`, `gh-pages-ready` тегами `archive/*` и удалить ветки; рабочую ветку сделать веткой по умолчанию на GitHub. Ничего не теряется.

### 2. Два деплоя, и ни один не работает автоматически

- `.github/workflows/deploy-pages.yml` ждёт пуша в **`proto-3d`** и требует `Settings → Pages → Source: GitHub Actions`
- Pages фактически раздаёт ветку **`gh-pages`** (проверено: живая страница совпадает с `gh-pages:index.html`)
- работа идёт в **`hybrid-v8`**

Итого пуш рабочей ветки не деплоит ничего, `gh-pages` собирается руками. Варианты: перевести workflow на рабочую ветку и переключить Source на Actions (тогда пуш = деплой), либо удалить workflow и оставить ручную схему, добавив `deploy.sh`.

Уборка размер `.git` не уменьшила — блобы остаются в истории. Лечится `git filter-repo` + force-push: отдельная осознанная операция, ломает существующие клоны.

### 4. Разобрать архив

`_ARCHIVE/` весит около 1.2 ГБ. Самый безопасный кандидат на удаление — папка `3 - копии текущего сайта` (490 МБ, уникального содержимого нет). `4 - рабочие материалы` удалять не стоит: там мастера роликов, пережать заново будет неоткуда.
