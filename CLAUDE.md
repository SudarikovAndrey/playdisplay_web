# PLAYDISPLAY — паспорт проекта (для Claude)

Сайт студии интерактивного опыта PlayDisplay. Язык: русский. Владелец: Андрей Судариков.

## Структура папки
Полная карта — в `CONTENT-MAP.md`. Коротко: в репозитории **только текущий сайт**.

```
site/                 ← сайт целиком, единственный источник правды. Самодостаточен: ссылок за свои пределы не имеет
site/api/             ← бэкенд AI-ассистента на PHP. Своя документация — site/api/README.md
build_seo.py          ← генератор /work/<slug>/, sitemap, robots, llms, SEO-блока главной
download_assets.sh    ← докачка картинок проектов в site/assets/work/
CLAUDE.md  README.md  CONTENT-MAP.md
_ARCHIVE/             ← вне git: прошлые поколения сайта, слепки site/, сырьё. См. _ARCHIVE/README.md
```

Прошлые поколения (бренд-платформа 2026 в корне, 3D-прототип в `dist/` и `proto 3d/`) выведены из отслеживания 27.07.2026 и лежат в `_ARCHIVE/`. Точка возврата — тег `archive/before-cleanup`.

## Деплой — цепочка из трёх звеньев
Ветка `gh-pages` — не только для GitHub Pages: с неё же тянет боевой хостинг. Одна ветка, две площадки.

1. **Рабочая ветка `hybrid-v8`** — здесь правится `site/`. Все коммиты `proto-3d` в неё входят, сама `proto-3d` отстала и не используется.
2. **Ветка `gh-pages`** — содержимое = `site/` без верхней папки. Пересборка:
   `git archive hybrid-v8 site | tar -x --strip-components=1` + `.nojekyll`, новый коммит поверх текущей gh-pages (fast-forward, без force).
   Пуш делает Андрей: `git push origin hybrid-v8 gh-pages` (у песочницы нет git-кредов).
3. **Хостинг timeweb** — папка `~/wordpress_2/public_html` это git-клон репозитория на ветке `gh-pages`, лежащий прямо в корне сайта. Обновление одной командой по SSH (`ssh pdisplay@vh432.timeweb.ru`) или в SSH-консоли панели:
   `cd ~/wordpress_2/public_html && git pull --ff-only origin gh-pages`

Адреса: превью https://sudarikovandrey.github.io/playdisplay_web/ · боевой https://playdisplay.com и https://playdisplay.ru (обе привязаны к одной папке, canonical у обеих на `.com`).

**Переезд в корень домена состоялся 28.07.2026.** До этого новый сайт жил в подпапке `/new/`, а в корне стоял WordPress 2021 года. Что изменилось:
- WordPress вынесен из веба в `~/wordpress_2/wp_old_root` (база не тронута). Папку `/new/` подняли в корень вместе с `.git`, сама `new` удалена.
- Статичный слепок старого сайта лежит в `~/wordpress_2/public_html/old` → https://playdisplay.com/old/ — 646 файлов, 244 МБ, снят `wget -m -p -k -E -nH`. У него свой `.htaccess` с `X-Robots-Tag: noindex, nofollow`. В архиве 21 страница работ, из них 6 (`jihi-studio-lamp`, `holocube_s`, `petrol-bowl`, `summer-17`, `changi2016`, `оживайка`) на новом сайте отсутствуют — возможно, стоит перенести.
- Герой архивной главной — фоновое видео с Vimeo (id 455829149), wget его забрать не мог. В конец `old/index.html` дописан скрипт-вставка iframe; видео всё равно не проигрывается (нужен приватный хеш встройки), фон сделан чёрным.
- `site/.htaccess` теперь в репозитории и держит редиректы со всех старых адресов вордпресса, закрывает `.git` и задаёт mime/кэш. Раньше `.htaccess` жил на сервере незакоммиченным.

Сборку пакетов для ручной загрузки (был скрипт `build_upload.py` и папка `deploy/`) убрал 27.07.2026: доставка идёт через `git pull`, второй способ только создавал расхождение между сервером и репозиторием.
- **Открытый вопрос:** `.github/workflows/deploy-pages.yml` триггерится на пуш в `proto-3d` и требует `Settings → Pages → Source: GitHub Actions`. Сейчас это не совпадает ни с рабочей веткой, ни с реальным каналом раздачи, поэтому автодеплой не срабатывает и gh-pages собирается руками. Решение — либо перевести workflow на рабочую ветку, либо удалить workflow. Пока не решено, воркфлоу не трогать.
- `origin/HEAD` смотрит на `main`, где лежит один «Initial commit» — поэтому GitHub по умолчанию открывает пустую ветку. Ветки `master`, `gh-pages-new`, `gh-pages-ready` — старьё, к работе отношения не имеют.
- Локальный тест: сервер в песочнице умирает между вызовами bash; тестировать на живом gh-pages или через file-инструменты.
- Песочница иногда оставляет `.git/*.lock` после своих коммитов; если git ругается «Another git process» — снять `.git/HEAD.lock`, `.git/index.lock`, `.git/objects/maintenance.lock`.

## Параллельная работа в нескольких чатах
Владелец иногда ведёт несколько чатов одновременно (например миниигра в одном, контент в другом). Изоляции между ними нет: все правят одни и те же файлы на диске, и последняя запись перетирает чужую.

- **Территории.** Миниигра и 3D-сцена — `site/hero-scene.html`. Контент, лендинг, данные, документация — `site/index.html`, `site/data/*`, `*.md`. AI-ассистент — `site/api/*` целиком плюс два блока в `index.html`: панель `#ai` с её CSS и скрипты `window.pdIdea`/`window.pdSpeech`. Связка лендинга с игрой (`pdGame`, `pdPlay`, лоадер) живёт в `index.html` — если её нужно править из игрового чата, сначала сказать владельцу. `index.html` — самый спорный файл: перед правкой перечитать.
- **Перед работой** — `git status` и `git log -1`. Если в рабочей копии чужие незакоммиченные правки, не трогать их и спросить владельца.
- **Коммитит и деплоит один чат.** Два агента в одном `.git` дают залипшие `.git/*.lock` и битый индекс.
- **Ритуал деплоя не прерывается:** коммит в `hybrid-v8` → пересборка `gh-pages` → `git push origin hybrid-v8 gh-pages` → `git pull` на сервере. Если между пересборкой и пушем кто-то успел закоммитить, в `gh-pages` уедет неполная картина.
- **Признак столкновения:** Edit не находит фрагмент, который точно был, или файл выглядит иначе, чем ожидалось. Это значит, что файл изменил другой чат — перечитать, а не перезаписывать.

## Ключевые файлы
- `site/index.html` — весь лендинг-SPA: стили, CASES (15 проектов), сетка Work, кейс-вьюер (#viewer), WebGL-движок переходов FlyGL, роутинг (#work, #/work/<slug>).
- `site/hero-scene.html` — 3D hero (Three.js r128, облако точек), встраивается iframe'ом. Свой мобильный профиль настроек (localStorage `pd_proto_settings_m`), панель настроек по ссылке `?cam=1`.
- `site/data/projects.json` — весь контент кейсов (goal/solution/flow-блоки: h/p/steps/notes/stats/img/yt/vimeo). Вьюер строит страницы из него.
- `build_seo.py` — генерит статические `/work/<slug>/index.html`, sitemap.xml, robots.txt, llms.txt и SEO-блок главной (между маркерами `<!--SEO-->…<!--/SEO-->`). Требует /tmp/cases.json (извлекается из CASES). После изменения структуры/контента — перегенерить.
- `download_assets.sh` — докачка картинок проектов; сжатые копии уже в site/assets/work/. Мастера роликов — в `_ARCHIVE/4 - рабочие материалы/videos/`, сжатые ролики — `site/videos/`.
- `site/data/atlas.json` — Атлас: 50 карточек в пяти типах (Принцип 20, Приём 13, Наблюдение 8, Технология 5, Исследование 4). Тип «Концепт» убран 28.07.2026: готовые идеи решений дублировали библиотеку концепций, Атлас оставлен про слои знания. Источник — `PlayDisplay_Атлас_единая_структура_v2.docx` в рабочих материалах; прежние 32 карточки с разборами убраны по решению владельца 28.07.2026. Подписи фильтра во множественном числе лежат в `catLabels`, поле `cat` у карточки — в единственном (это бейдж). Сейчас у карточек только `title` + `desc`, поэтому все они тезисы: класс `.thesis`, клик не навешивается, вьюер разбора не открывается. Как только у карточки появятся `principle` и `examples` — она сама станет кликабельной, рендер это поддерживает.
- `site/data/concepts.json` — библиотека авторских концепций (раздел #concepts).
- `site/api/` — **AI-ассистент**: разговор с посетителем → бриф → письмо Андрею. PHP без зависимостей,
  единая точка входа `api/ai.php` (действия ping/start/turn/brief/send). Подробно — `site/api/README.md`.
  Характер разговора (что и как спрашивать) живёт в `api/lib/prompts.php` и правится без кода.
  Драйверы модели (`mock`/`anthropic`/`openai_compat`/`gigachat`) и почты (`file`/`smtp`/`mail`) меняются
  одной строкой конфига. **Ключей в репозитории нет:** конфиг — `api/config.php` (в .gitignore) или,
  на боевом, `~/wordpress_2/pd-ai-config.php` выше веб-корня. Проверка настроек — `/api/selftest.php`.
  Без конфига работают драйверы `mock`+`file`: весь путь проходится без сети, письмо ложится в `api/outbox/`.
  На стороне клиента: `window.pdIdea` (транспорт, демо-фолбэк) и `window.pdSpeech` (Web Speech API,
  ru-RU, склейка реплики по паузе 1,5 с, переподъём после самопроизвольного обрыва в Chrome) —
  оба в `index.html`. Ввод текстом равноправен голосу: в Firefox распознавания нет вовсе.
  Внимание: на превью GitHub Pages PHP не исполняется и `api/*.php` отдаётся исходником —
  секретов в этих файлах нет, клиент распознаёт «не JSON» и честно уходит в демо-режим.

## Что отстроено и НЕ ломать при пересборке
- **FlyGL** (site/index.html): WebGL-переход в кейс и обратно. Влёт: прямоугольная волна растворения от карточки с искрами по фронту, пиксельные частицы с motion-стрейком, морфинг обложки в кадр, сборка страницы (кадр+тексты) из объёмного облака, перекраска зерна живым видео. Вылет: растворение страницы без видимого фронта, финальная волна сходится и «упирается» в карточку-цель, интерьер открыт заранее, фиксация-свечение контура + искры на периметре. Отладка: `?flyslow` (×3 медленнее), `window.__flyK=0.5` (заморозка фазы). Фолбэк без WebGL — быстрый фейд. Слабое железо/мобила — реже сетка частиц.
- Ховер карточек: пыль-магнит с соседних обложек (canvas #cards-fx). На мобиле карточки сразу цветные (без ховера).
- Hero: постоянная связка postMessage лендинг↔iframe (pdVisible, pdMeta, pdPlay, pdScroll, pdRotate, pdTapPlay, pdReady, pdGame, pdCam). Тёмный лоадер с белым лого; верхняя панель выезжает по pdReady. Кликабельный логотип → верх страницы. Портрет: FOV авто-подстраивается (portraitFitFov), cover не зумится; тап = play/стоп.
- Кейс-вьюер: медиа (локальное видео/встройки/картинки), плашки-меты, статы, flow-блоки с каскадным появлением (.settled), галереи-листалки, «следующий проект», lightbox.
- Мобильные фиксы: без бокового скролла, user-select off в hero, cursor:none только при pointer:fine (иначе пропадает курсор).
